## M-07 エディターの構文ハイライト

### A. 明るいテーマ

1. Joplin のテーマを「明るい」にして、テスト用のノートを Markdown エディターで開く。
2. **確認**：1 と 1b のブロックで、次のものが色分けされる。色そのものは Joplin のエディターのテーマの色でよい（ほかの言語のコードブロックのキーワードや文字列と同じような色になる）。
   - `@startuml`、`@enduml`（太字）
   - キーワード（`skinparam`、`participant`、`as`、`actor`、`class`）
   - `!theme`
   - コメント（`' a line comment` と、2行にわたる `/' … '/`）
   - 文字列（`"Web server"`）
   - 矢印（`->`、`-->`、`<|--`、`..>`）
   - 色（`#FF0000`、`#LightBlue`）
3. **確認**：`:` の後のラベル（`request (this label is not coloured: class note ->)`）は色分けされない。
4. **確認**：2 の4文字のフェンスとチルダのブロックも色分けされる。
5. **確認**：3 の `js` と `text` のブロックは、このプラグインでは色分けされない（`js` は Joplin 本体の色分けのままでよい）。
6. **確認**：入力しても重くならない。1 のブロックに文字を打つと、色分けがすぐに追従する。

### B. 暗いテーマ

1. Joplin のテーマを「暗い」にする。
2. **確認**：A と同じものが、暗い背景の上で読みやすい色で色分けされる。

### C. 設定

1. 「ほかの言語名」（Other language names）に `uml` を入れて、ノートを開き直す（ほかのノートを開いてから戻る）。
   - **確認**：4 の `uml` のブロックも色分けされ、ビューアでも図として表示される。
2. 「Markdown エディターで PlantUML を色分けする」を切って、ノートを開き直す。
   - **確認**：PlantUML のブロックが色分けされなくなる。設定を戻してノートを開き直すと、また色分けされる。
3. 後片付け：「ほかの言語名」を空に戻す。

---

## エラーの抜粋の色分け（7.4節）

1. ビューアで 5 のブロックを見る。
2. **確認**：エラーボックスの該当行の抜粋（`class Order #red ->> this is wrong`）で、`class` と `#red` と矢印が色分けされる。
3. Joplin のテーマを「暗い」にしても、抜粋の色が暗い背景の上で読める。
