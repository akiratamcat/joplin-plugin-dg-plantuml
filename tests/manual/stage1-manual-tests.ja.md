# 段階1 の手動テスト：M-01 と M-16

設計書 16.3節の手動テストのうち、段階1（MVP）で残っている2項目の手順。ほかの項目（M-02、M-03、M-06、M-08、M-09、M-14）は、手順3 で [mvp-note.md](mvp-note.md) を使って確認済み。

| 項目     | 内容                                                                                 |
| -------- | ------------------------------------------------------------------------------------ |
| 対象     | `publish/io.github.akiratamcat.dg-plantuml.jpl`（版数 0.1.0）。`npm run dist` で作る |
| 環境     | Joplin の最新の安定版（Windows）                                                     |
| 所要時間 | M-01 が約 15分、M-16 が約 10分                                                       |

プラグインのインストール、更新、無効化、削除は、どれも Joplin の再起動を求められる。求められたら再起動する。

## M-01 インストールと更新

### 準備

- 更新の確認用に、版数だけを 0.1.1 に変えた `.jpl` を使う。中身は 0.1.0 と同じ。Claude が作業用のフォルダに作ったもので、そのフォルダは消えることがある。見つからないときは、作り直すよう Claude に頼む。
- 試作のプラグイン（`...dg-plantuml.spike`）が残っていれば、先に削除しておく。

### A. 新規インストール

1. 設定 → プラグインで、dg-plantuml が入っていれば削除して、Joplin を再起動する。
2. 歯車のアイコン →「ファイルからインストール」で `publish/io.github.akiratamcat.dg-plantuml.jpl` を選び、再起動する。
3. **確認**：プラグインの一覧に「dg-plantuml」が版数 0.1.0 で表示される。
4. **確認**：[mvp-note.md](mvp-note.md) のノートを開くと、図が表示される。

### B. 更新

1. 「ファイルからインストール」で 0.1.1 の `.jpl` を選び、再起動する。
2. **確認**：プラグインの一覧で、版数が 0.1.1 になっている。dg-plantuml が2つ並んでいない。
3. **確認**：mvp-note のノートの図が、前と同じく表示される。
4. 後片付け：`publish/io.github.akiratamcat.dg-plantuml.jpl`（0.1.0）をインストールし直して、再起動する。

### C. 無効化と再有効化

1. プラグインの一覧で、dg-plantuml のスイッチを切り、再起動する。
2. **確認**：mvp-note のノートで、PlantUML のブロックが普通のコードブロック（ソースの文字）として表示される。エラーは出ず、Mermaid の図は表示される。
3. スイッチを入れ、再起動する。
4. **確認**：PlantUML の図が再び表示される。

### D. 削除

1. dg-plantuml を削除して、再起動する。
2. **確認**：mvp-note のノートで、PlantUML のブロックが普通のコードブロックとして表示される。
3. **確認**：Markdown エディタで見ると、ノートのソースは変わっていない。フェンスやオプション（`theme=dark` など）がそのまま残っている。
4. 後片付け：0.1.0 の `.jpl` をインストールし直して、再起動する。

## M-16 大きな図・異常な入力

### 準備

1. [m16-large-and-broken.md](m16-large-and-broken.md) を VS Code などで開き、すべてを選択してコピーする。約 150KB あり、とても長い行を含む。
2. Joplin で新しいノートを作り、Markdown エディタに貼り付ける。

このノートは [generate-m16-note.cjs](generate-m16-note.cjs) で作ったもの。ブロックを変えるときは、スクリプトを直して作り直す。

### 手順と確認

1. **確認**：ノートを表示すると、10個のブロックが数秒のうちにすべて表示される。図またはエラーボックスで、それぞれ見出しの下の「Expected」のとおりになる。
   - 1〜3：行番号つきのエラー（無限ループ、無限の再帰、壊れた入力）
   - 4〜7：図。4 は空の図なので、何も見えなくてよい
   - 8：エンジンのエラー「Diagram too large for browser rendering ... (max 8192 ...)」
   - 9：意味の読めないエンジンのメッセージのエラー（`java.lang.UnsupportedOperationException ...`）。固まらなければよい
   - 10：エラー「The diagram is too large.」（エンジンは呼ばれない）
2. **確認**：表示されるまでの間も、Joplin が固まらない。ノートの一覧のスクロールや、別のノートへの切り替えができる。
3. **確認**：7（200個のクラスの図）のブロックの中で、Markdown エディタで文字を打つ（例: `class C0` を `class C0x` にする）。入力が大きく遅れたり止まったりしない。図は少し遅れて描き直される。
4. **確認**：別のノートに切り替えてから、このノートに戻る。図がすぐに表示される（キャッシュから表示される）。
5. 後片付け：テスト用のノートを削除する。
