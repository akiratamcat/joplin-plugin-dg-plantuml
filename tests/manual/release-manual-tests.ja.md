# リリース前の手動テスト

設計書 16.3節の手動テスト（M-01〜M-16）を、リリースの前に行うための手順書。v1.0.0 から、リリースのたびにこの手順で確かめ、結果を末尾の「記録」に書く。生成 AI を使わずに進められるように書いてある。

| 項目             | 内容 |
| ---------------- | ---- |
| 対象             | リリースする版の `.jpl`（`io.github.akiratamcat.dg-plantuml.jpl`）。入手の方法は下の「準備」 |
| 環境と範囲       | 下の表のとおり。Joplin は各環境の最新の安定版を使う |
| テスト用のノート | [mvp-note.md](mvp-note.md)、[stage2-note.md](stage2-note.md)、[stage4-note.md](stage4-note.md)、[release-links-note.md](release-links-note.md)、[m16-large-and-broken.md](m16-large-and-broken.md) |
| 所要時間         | フルテストが 60〜90分、スモークテストが約 15分 |

| 環境                   | 範囲 | いつ |
| ---------------------- | ---- | ---- |
| Windows（x64）         | フルテスト（全項目） | 毎回のリリース前 |
| macOS（Apple silicon） | MAJOR・MINOR の版はフルテスト、PATCH の版はスモークテスト | 毎回のリリース前 |
| Linux（x64）           | スモークテスト | MAJOR・MINOR の版のリリース前 |

- **スモークテスト**は、見出しに「スモーク」と書いた項目（M-01、M-02、M-03、M-04、M-06、M-07、M-15）だけを行う。
- v1.0.0 は MAJOR の版なので、Windows と macOS はフルテスト、Linux はスモークテストを行う。
- プラグインのインストール、更新、無効化、削除と、表示言語の変更は、Joplin の再起動を求められる。求められたら再起動する。
- 設定は、設定（macOS は Joplin → 設定）→ プラグイン →「dg-plantuml」にある。詳細設定の項目は「詳細設定を表示」で出る。設定を変えると、ノートに戻ったときに図が描き直される。
- 設定やエラーの名前は、Joplin の表示言語が日本語のときのもの。

## 準備

### .jpl の入手

- **Windows（開発用の PC）**：リポジトリで `npm ci` と `npm run dist` を実行すると、`publish/io.github.akiratamcat.dg-plantuml.jpl` ができる。
- **macOS・Linux など、開発環境のない PC**：GitHub のリポジトリの **Actions** タブ → main の最新の「CI」の実行 → 下の方の **Artifacts** の「plugin-package」をダウンロードする（GitHub にログインしている必要がある）。zip を展開すると `.jpl` が入っている。中身は Windows で作るものと同じ。

### テスト用のノートの入手

- GitHub のリポジトリのページで `tests/manual/` の各ファイルを開き、右上の「Copy raw file」のボタンでコピーできる。開発用の PC では、ファイルを VS Code などで開いてコピーしてもよい。
- Joplin で新しいノートを作り、Markdown エディターに貼り付ける。ノートの番号（見出しの番号）を手順の中で使う。
- テスト用のノートは、テストが終わったら削除してよい。

### 始める前に

- Joplin を最新の安定版に更新する（ヘルプ → 更新を確認）。
- 前のテストで入れた dg-plantuml があれば、M-01 の A の手順で入れ直す。
- M-15 では、Joplin の同期を止めておく（同期の通信と見分けやすくするため）。

## M-01 インストールと更新（スモーク）

### A. 新規インストール

1. 設定 → プラグインで、dg-plantuml が入っていれば削除して、再起動する。
2. 歯車のアイコン →「ファイルからインストール」で `.jpl` を選び、再起動する。
3. **確認**：プラグインの一覧に「dg-plantuml」が、リリースする版の版数で表示される。
4. **確認**：mvp-note のノートを開くと、図が表示される。

### B. 更新（Windows だけ）

1. 前の版の `.jpl` を入れた状態から、今回の `.jpl` を「ファイルからインストール」で入れ、再起動する。
   - 前の版の `.jpl` は、GitHub の Releases から入手する。v1.0.0 のように前の版がないときは、`package.json` と `src/manifest.json` の `version` を一時的に上げて `npm run dist` で作った `.jpl`（中身は同じで版数だけが違う）に入れ替えて確かめ、版数は元に戻す。
2. **確認**：版数が新しくなり、dg-plantuml が2つ並んでいない。
3. **確認**：mvp-note の図が、前と同じく表示される。
4. 後片付け：テストする `.jpl` を入れ直して、再起動する。

### C. 無効化と再有効化

1. プラグインの一覧で dg-plantuml のスイッチを切り、再起動する。
2. **確認**：mvp-note で、PlantUML のブロックが普通のコードブロック（ソースの文字）として表示される。エラーは出ず、12 の Mermaid の図は表示される。
3. スイッチを入れ、再起動する。
4. **確認**：PlantUML の図が再び表示される。

## M-04 テーマの切り替え（スモーク）

stage2-note を使う。

1. 設定が既定（PlantUML の図のテーマ：自動、明るいテーマのときのスタイル：PlantUML 標準（明るい配色、既定）、暗いテーマのときのスタイル：PlantUML ダーク（暗い配色、既定））であることを確かめる。
2. Joplin のテーマを Light 系にする。
   - **確認**：1〜6 が PlantUML 標準の見た目で、背景は透明。
3. Joplin のテーマを Dark 系にする。
   - **確認**：1〜6 が暗い配色になり、読みやすい。
4. **確認**：どちらのテーマでも、7 の3つのブロックはオプションどおり（Light 系では `theme=dark` に暗い背景、Dark 系では `theme=light` と `theme=none` に白い背景が敷かれる）。
5. PlantUML の図のテーマを「明るい」にして、Joplin を Dark 系にする。
   - **確認**：図が明るい見た目になり、白い背景が敷かれて読める。
6. PlantUML の図のテーマを「暗い」にして、Joplin を Light 系にする。
   - **確認**：図が暗い見た目になり、暗い背景が敷かれて読める。
7. 明るいテーマのときのスタイルを「PlantUML のテーマ: Cerulean」、暗いテーマのときのスタイルを「PlantUML のテーマ: Cyborg」にして、Light 系と Dark 系で見る。
   - **確認**：色が変わり、エラーにならない。
8. 後片付け：PlantUML の図のテーマを「自動」に、2つのスタイルを既定に戻す。

## M-05 文字サイズ

stage2-note を使う。

1. ノートビューアのペインを細くする（エディターとビューアの境目をドラッグする、またはウィンドウを狭くする）。
   - **確認**：6 の横に長い図は縮小されるが、文字は小さくなりすぎず（既定は 11px まで）、はみ出した分は横スクロールで見られる。
2. ペインを広くする。
   - **確認**：図が広い幅に合わせて描き直される。1 のような小さい図は、ペインを細くしても等倍のまま。
3. 「縮小表示するときの最小の文字サイズ（px）」を 0 にする。
   - **確認**：6 がペインの幅に収まる（文字はとても小さくてよい）。11 に戻す。
4. **確認**：1〜6 の図の文字の大きさが、ノートの本文の文字とほぼ同じ。8 は図の中の指定どおり小さいまま。
5. 「図の文字サイズをノートの文字に合わせる」を切る。
   - **確認**：図の文字が PlantUML 標準の大きさに戻る。設定を戻す。

## M-07 エディターの構文ハイライト（スモーク）

stage4-note を使う。

2. **確認**：1 と 1b のブロックで、`@startuml`・`@enduml`、キーワード（`participant`、`class` など）、`!theme`、コメント、文字列、矢印、色（`#FF0000`）が色分けされる。`:` の後のラベルは色分けされない。
3. **確認**：2 の4文字のフェンスとチルダのブロックも色分けされる。3 の `js` と `text` のブロックは、このプラグインでは色分けされない。
4. Joplin のテーマを Dark 系にする。
   - **確認**：同じものが、暗い背景の上で読みやすい色で色分けされる。
5. **確認**：ビューアで 5 のエラーボックスの抜粋（`class Order #red ->> this is wrong`）が色分けされる。

## M-10 図のツールバー

release-links-note を使う。

1. 1 の図にマウスを乗せる。
   - **確認**：図の右上にツールバー（5つのボタン）が出る。ボタンにマウスを乗せると説明が出る。
2. 「SVG をコピー」を押し、テキストエディターに貼り付ける。
   - **確認**：`<svg` で始まる SVG のテキストが貼り付けられる。
3. 「PNG をコピー」を押し、画像を貼り付けられるアプリ（ペイント、プレビューなど）に貼り付ける。
   - **確認**：図の画像が貼り付けられる。4（暗い図）で同じことをすると、暗い背景の画像になる。
4. 「SVG を保存」と「PNG を保存」を押し、フォルダを選ぶ。
   - **確認**：選んだフォルダに、ノートの題名から作った名前のファイルが保存され、完了の知らせが出る。保存したファイルを開くと図が見える。
5. 「PlantUML のソースをコピー」を押し、テキストエディターに貼り付ける。
   - **確認**：1 のブロックの PlantUML のソースが貼り付けられる。
6. （できれば）Tab キーで図のボタンに移り、Enter キーで押せることを確かめる。
7. 「図のツールバーを表示する」を切る。
   - **確認**：マウスを乗せてもツールバーが出ない。設定を戻す。

## M-11 図の中のリンク

release-links-note を使う。ノートの説明のとおり、2 のノート ID を実際のノートの ID に書き換えておく。

   - **確認**：書き換えた ID のノートが Joplin で開く。ビューアのページが別のページに切り替わったりしない。
2. 元のノートに戻り、2 の「PlantUML website」をクリックする。
   - **確認**：既定のブラウザーで https://plantuml.com/ が開く。
3. 3 の「Local file」をクリックする。
   - **確認**：何も開かない（`file:` のリンクは開かない決まり）。Joplin のエラーやページの切り替わりも起きない。

## M-12 設定画面

1. **確認**：設定 → プラグイン → dg-plantuml に、すべての設定項目が表示される。冒頭にプラグインの説明文、最下部（詳細設定の上）に「同梱している外部のソフトウェア」の選択リストがあり、開くと5行が並ぶ。
2. 詳細設定の項目を変えて、図に反映されることを確かめる。
   - 「ソースの最大文字数」を 1000 にして stage2-note の 6 を見る。**確認**：「図が大きすぎます。」のエラーになる。100000 に戻す。
   - 「図で使用するフォント」に `Courier New` などを入れる。**確認**：図の文字のフォントが変わる。空に戻す。
   - 「ほかの言語名」に `uml` を入れる。**確認**：stage2-note の 9 が図として表示される。空に戻す。
3. 後片付け：変えた設定をすべて既定に戻す。

## M-13 表示言語

表示言語は、設定 → 全般 →「言語」で変え、再起動する。

1. 日本語にする。
   - **確認**：dg-plantuml の設定画面が日本語になる。mvp-note の 9 のエラーボックスが「PlantUML のエラー」「3 行目: …」になる（後半のエンジンのメッセージは英語のまま）。
2. English にする。
   - **確認**：設定画面とエラーボックスが英語になる。
3. 中文 (简体) にする。
   - **確認**：設定画面とエラーボックスが中国語（簡体字）になり、文字化けがない。
4. 後片付け：普段の表示言語に戻す。

## M-14 リッチテキストエディター

mvp-note を使う。

1. ノートをリッチテキストエディターで開く。
   - **確認**：PlantUML の図が、12 の Mermaid と同じように図として表示される。
2. 1 の図をダブルクリックして、Joplin の編集画面でソースを少し変え、OK を押す。
   - **確認**：図が描き直される。
3. Markdown エディターに戻す。
   - **確認**：変えたところ以外のソースが壊れていない。空行が増えていない。4 の `theme=dark align=left` などのブロックのオプションが残っている。
   - 4文字以上のフェンスが3文字に変わるのは、Joplin 本体の制約として許容する（README の制限事項）。

## M-15 外部通信なし（スモーク）

1. Joplin の同期を止める。
2. ヘルプ → 開発者ツールの切り替え で開発者ツールを開き、Network（ネットワーク）タブを選ぶ。
3. mvp-note と release-links-note を表示し、図を編集し、Joplin のテーマを切り替え、ツールバーのコピーと保存を行う。
4. **確認**：Network タブに、外部（`http://` や `https://`）への通信が出ない。プラグイン自身のファイル（`plantuml.js` などのローカルのファイル）を読む記録は出てよい。
5. （さらに厳しく確かめる場合）OS のファイアウォールで Joplin の外向きの通信だけを遮断する規則を作り、図が描けることを確かめる。終わったら規則を削除する。
6. 後片付け：同期を元に戻す。

## M-16 大きな図・異常な入力

1. m16-large-and-broken.md の全体を新しいノートに貼り付ける（約 150KB）。
2. **確認**：10個のブロックが数秒のうちに表示される。それぞれ見出しの下の「Expected」のとおりになる。
3. **確認**：表示されるまでの間も Joplin が固まらない。ノートの一覧のスクロールや、別のノートへの切り替えができる。
4. **確認**：7（200個のクラスの図）のブロックで文字を打っても、入力が大きく遅れたり止まったりしない。
5. 後片付け：このノートを削除する。
